# Documentation Lifecycle — Жизненный цикл документации

> Обновляет: Technical Writer.
> Когда обновляется: при добавлении нового типа документа в систему.
> Используют: все роли — для понимания, что можно менять и как часто.
> Обязателен: да.

## Никогда не меняются (immutable)
- Закрытые записи в `/reports` (аудиты, code review, QA-отчёты прошлых задач)
- `/releases/*` после публикации релиза
- История `templates/decision.md` — старые решения не переписываются, только дополняются новым решением со ссылкой на предыдущее

## Редко меняются
- `PROJECT_RULES.md` — только по решению Owner
- `AI_CONTEXT.md` — при изменении архитектуры/стека
- `DEFINITION_OF_DONE.md` — после ретроспектив
- Промпты ролей в `/prompts`
- Шаблоны в `/templates` и чек-листы в `/checklists`

## Обновляются после каждого этапа
- `CURRENT_STATUS.md`
- `/ai/DASHBOARD.md`
- `/specifications/*` (при изменении контракта API/БД)

## Обновляются автоматически (при наличии скриптов в `/scripts`)
- Раздел «Последний Commit» в `DASHBOARD.md`
- Статус сборки / тестов
- Счётчик открытых багов

## Архивируются
- Завершённые спринты → `reports/sprint_archive/`
- Закрытые релизы старше N версий → `releases/archive/`
- Устаревшие спецификации, заменённые новыми → `specifications/archive/` с пометкой даты и причины замены

## Правило архивирования
Ничего не удаляется физически из истории проекта — только переносится в
`archive/` с сохранением оригинальной даты создания. Это нужно, чтобы через
годы можно было восстановить логику любого решения.
