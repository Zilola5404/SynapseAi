# Git Workflow

> Обновляет: Chief Architect / Senior Developer.
> Когда обновляется: при изменении процесса ветвления или CI/CD.
> Используют: Developer, Reviewer, Release Manager.
> Обязателен: да.

## Git Flow
- `main` — только production-готовый код
- `develop` — интеграционная ветка текущего этапа
- `feature/<кратко-на-английском>` — новая функциональность, от `develop`
- `bugfix/<кратко>` — исправление некритичного бага, от `develop`
- `hotfix/<кратко>` — срочное исправление production, от `main`
- `release/<версия>` — стабилизация перед релизом, от `develop`

## Pull Request
- PR создаётся из `feature/*` или `bugfix/*` в `develop`
- Описание PR обязано содержать: что сделано, зачем, как проверено (см. `templates/task.md`)
- PR не может быть смерджен без пройденного Code Review

## Code Review
- Выполняется ролью Reviewer (Principal Engineer), не автором изменений
- Результат фиксируется в `templates/code_review.md`
- Комментарии PR не заменяют файл отчёта — отчёт обязателен для истории

## Merge
- Только через Pull Request, без прямых push в `develop`/`main`
- Squash или обычный merge — по конвенции проекта, фиксируется в `AI_CONTEXT.md`

## Release
- Ветка `release/<версия>` стабилизируется, проходит QA и финальный Audit
- После подтверждения — merge в `main` и тег версии
- Заполняется `templates/release.md`, обновляется `/releases/CHANGELOG.md`

## Hotfix
- От `main`, минимальные изменения, обязательный ускоренный Code Review + smoke-тест
- После слияния — обратный merge в `develop`, чтобы исправление не потерялось

## Rollback
- Каждый релиз обязан иметь задокументированный план отката в `templates/release.md`
- Откат — это возврат на предыдущий тег `main` + фиксация причины в `reports/`

## Правила Commit-сообщений

Все Commit-сообщения пишутся **только на русском языке**, простыми и понятными
формулировками. Из сообщения должно быть понятно, что изменено, даже через
несколько месяцев.

**Запрещены** сообщения вида: `fix`, `update`, `changes`, `bugfix`, `temp`,
`test`, `work`, `commit`, `final`.

**Правильные примеры:**
- Добавлена авторизация по JWT
- Исправлена ошибка подключения к PostgreSQL
- Реализован VPN Tunnel Hysteria2
- Добавлен экран настроек Android
- Исправлена утечка памяти в Relay Service
- Добавлена проверка лицензии
- Обновлена документация архитектуры
- Добавлены интеграционные тесты Billing

Перед созданием Commit исполнитель обязан убедиться, что проект успешно
собирается и все выполненные изменения работоспособны.
