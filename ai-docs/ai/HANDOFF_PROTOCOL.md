# AI Handoff Protocol — Стандарт передачи задачи между ИИ

> Обновляет: Control Center.
> Когда обновляется: при выявлении пробелов в передаче задач (ретроспектива).
> Используют: все роли — обязателен при каждом переходе задачи с этапа на этап.
> Обязателен: да, без исключений.

## Что обязательно передаётся

1. **Идентификатор задачи** (`TASK-XXX` / `BUG-XXX`) и ссылка на исходный `templates/task.md`
2. **Что сделано** — конкретно, без общих формулировок
3. **Как проверено** — какие пункты самопроверки (`PROJECT_RULES.md`, статья 2) пройдены и какими способами
4. **Что НЕ проверено и почему** — явно, если что-то не удалось проверить
5. **Известные ограничения / компромиссы**, принятые при реализации
6. **Ссылки на изменённые файлы / коммиты**
7. **Статус относительно Definition of Done** — какие пункты выполнены

## Какие документы обновляются при каждом Handoff

- `CURRENT_STATUS.md` — активная задача переходит к следующей роли
- `DASHBOARD.md` — если меняется процент готовности, число багов и т.д.
- Отчёт своей роли в `/reports` (например, `reports/code_review_TASK-XXX.md`)

## Какие отчёты создаются

| Переход | Отчёт |
|---|---|
| Developer → Reviewer | `templates/code_review.md` (заполняет Reviewer после проверки) |
| Reviewer → Auditor | `templates/audit.md` |
| Auditor → QA | `templates/qa_report.md` |
| QA → Documentation | краткая заметка в `CURRENT_STATUS.md`: что задокументировать |
| Documentation → Release Manager | `templates/release.md` (черновик) |
| Release Manager → Owner | заполненный `templates/release.md` + чек-лист `before_production.md` |

## Как фиксируется завершение этапа

1. Ответственная роль отмечает выполненные пункты в соответствующем чек-листе из `/checklists`
2. Создаётся или обновляется запись в `/reports` с датой и подписью роли
3. `DASHBOARD.md` обновляется в течение той же сессии, а не «потом»
4. Только после этого задача считается официально переданной — до этого момента
   принимающая роль не обязана начинать работу

## Запрещено при передаче

- Передавать задачу без заполненного пункта «Как проверено»
- Передавать с известными ошибками без явного объявления (`PROJECT_RULES.md`, статья 3)
- Пропускать создание отчёта «чтобы не терять времени»
- Изменять статус задачи на «готово», если не пройдены пункты Definition of Done
